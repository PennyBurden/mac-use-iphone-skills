# 任务：铁路12306 查车次（只查不买）

## 定位

- 输入：出发地、目的地、日期（可选：时间段、车型偏好）。
- 输出：≤3 个符合条件的车次候选，含页面显示的时刻与票价信息。
- 考察点：日期选择、搜索、滚动、信息提取与结果核验。

## 硬边界

- **只读查询**：不点「预订」「购票」「提交订单」，不选乘车人，不进入任何下单链路。
- 不输入任何账号、密码、验证码、个人信息。遇到登录墙 → 停止交用户。
- 日期为过去 → 不操作，直接报告参数错误。
- v1 不进入车次详情页，票价只记录结果列表可见的信息。

## 流程

### 1. 检查

- 打开「铁路12306」。
- App 停留在异常状态（闪退重启、长时间加载）→ 按 recovery.md 处理。
- 首页查票一般无需登录；若查询被强制要求登录 → 停止，报告并交用户。

### 2. 设置查询条件（每项都要回读确认）

- 出发站：输入城市名 → 在联想列表中选择 → 回读输入框。
- 到达站：同上。注意多站城市（如北京有北京南、北京丰台），选默认推荐站并在汇报中注明实际所选站点。
- 日期：打开日期选择器 → 选择目标日期 → **回读查询栏显示的日期**，与用户要求的日期一致。
- 三项全部确认后才点「查询」。

### 3. 查询与等待

- 点「查询」后等待结果列表出现；加载中不点击任何按钮。
- 超过 15 秒未出结果 → 按 recovery.md 网络等待规则处理。

### 4. 提取候选

- 滚动浏览结果；每次滚动按核心操作循环验证页面真的移动。
- 按用户时间段筛选，取前 3 个候选。
- 每个候选记录：车次、出发/到达站、出发/到达时间、历时、票价（如列表可见；不可见则注明「列表未显示」）。

### 5. 核验

- 回到查询栏，确认「出发站 + 到达站 + 日期」与任务要求一致（防止搜成别的日期）。
- 时间窗内候选不足 3 个 → 如实报告实际数量，不放宽条件凑数。

### 6. 汇报

- 表格：车次 | 出发-到达 | 时间 | 历时 | 票价（页面显示）。
- 固定注明：「以上为查询当时页面显示；未进行任何购票操作；票价与余票实时变化。」

## 重试预算

- 查询动作（点查询 + 等结果）最多 2 次；条件设置单项最多 3 次。触顶停止报告。
