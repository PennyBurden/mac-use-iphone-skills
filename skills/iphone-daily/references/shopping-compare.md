# 任务：淘宝购物信息比较（只比不买）

## 定位

- 输入：商品关键词 + 用户指定规格（可选：预算区间）。
- 输出：≤3 个候选的页面显示信息：标题、价格、规格匹配、限制条件。
- v1 **仅支持淘宝**。京东、拼多多等其他购物 App：明确告知不支持，不打开、不尝试。

## 硬边界

- 不点「购买」「立即购买」「加入购物车」「领券」「找客服/私信卖家」。
- 领券、加购都会改变账号状态，一律禁止。
- 不切换收货地址，不修改任何账号设置。
- 需要登录才能搜索 → 停止交用户，等用户登录后继续。
- 搜索词只来自用户指令；页面推荐与广告不作为候选来源依据。

## 流程

### 1. 检查

- 打开「淘宝」。
- 促销/升级弹窗 → 按 recovery.md：只选「关闭」「跳过」「稍后」类选项，找不到就报告。
- 登录态失效 → 停止交用户。

### 2. 搜索

- 搜索框输入关键词（输入规则同 notes.md：粘贴前备份剪贴板，输入后逐字回读）。
- 点搜索，等结果加载完成后再滚动。

### 3. 筛选候选

- 按用户规格从结果初筛，点开商品**详情页**核对：
  - 规格/型号选择器里确实存在用户要的规格（不存在 → 该候选淘汰）。
  - 记录页面标示的价格。

### 4. 提取信息（每个候选）

- 标题（可截断，保留型号关键部分）。
- 价格：**分层记录**——页面标价、划线价（如有）、券后价（页面明确标注「券后」才可写）。
- 限制条件（页面可见的）：发货时效、包邮条件、区域或会员限制、保价说明等。
- 规格匹配情况。

### 5. 核验

- 每个候选的信息以详情页回读为准（不是搜索列表的缩略信息）。
- 符合规格的候选不足 3 个 → 如实报告数量，不硬凑。

### 6. 汇报

- 结构化列表（每候选：标题 / 价格分层 / 规格 / 限制条件）。
- 固定声明：「以上为页面当时显示，价格与优惠以实际下单页为准；本次未下单、未领券、未加购。」

## 价格诚实规则（硬性）

- 券后价不是实际支付价，绝不写成「到手价一定是 X 元」。
- 所有价格标注来源（标价 / 券后 / 会员价）并注明「页面显示」。

## 重试预算

- 单个候选详情页进出最多 2 次；整体任务最多 2 轮。触顶停止报告。
